# WSC → WS2 忠实转换

本文档记录 Willplus WSC 到 AdvHD WS2 的忠实转换知识：文件级对照、字节级模板、两代引擎的关键语义差异、切片模式与实现陷阱。转换器实现见 `galrev/convert/wsc2ws2.py`；来源侧引擎知识见 [../engines/willplus/wsc-opcodes.md](../engines/willplus/wsc-opcodes.md)，文件格式见 [../engines/willplus/file-formats.md](../engines/willplus/file-formats.md)。

凡标注「CROSS†CHANNEL 语料实测」的数字（脚本数、频次、标定值）都是**单一语料的统计或标定**，跨作品需重验；两代引擎的**机制结论**（指令语义、池模型、分发方式）不属此列。

## 1. 文件级对照

| | 原版 WSC | Steam WS2 |
|---|---|---|
| 字节混淆 | 每字节 ror 2（`galrev.willplus.decrypt.decrypt_wsc`） | 每字节 rot6（`galrev.advhd.ws2`） |
| 归档 | 类型表 + 21 字节定长条目、ASCII/Shift-JIS 名（`galrev.willplus.arc.read_old_arc`） | UTF-16LE 变长名（`galrev.advhd.arc`） |
| 文件头 | `8c <u16 全局脚本号> 00` + 可选 `e0 <章节标题>` | 无脚本头（引擎路由层承担） |
| 文件尾 | `0a 00` + `ff a b` | `07 <目标> 00 \| ff a b`（显式出口） |

原版按全局脚本号路由、大量选项块在文件尾由引擎分发；Steam 版要求每个脚本显式 `07|ff` 出口——这是文件级最大的结构差异，见 [../engines/willplus/file-formats.md](../engines/willplus/file-formats.md)。

## 2. 忠实转换的字节模板

以下模板全部取自 Steam 原生脚本语料与第三方补丁实测可玩块（CROSS†CHANNEL 语料），`<...>` 为变量段；**改一字节都可能让引擎少读/多读参数**，改动前先回原生语料核对。实现见 `galrev/convert/wsc2ws2.py` 的各 `emit_*`。

### 2.1 对话（WSC 0x41/0x42 → 15 + 14 + 15）

```
WSC 叙述:  41 <u16 id> 00 0f <文本 CP932> 00
WSC 对话:  42 <u16 id> 00 0f 0f <说话人 CP932> 00 <文本 CP932> 00
   ↓
WS2:       15 [00 | %LC<说话人> 00] 00            ← 设名（空前缀 = 旁白）
           14 <u16 id> 00 00 'char' 00 <文本> 00 00
           15 00 00                               ← 尾清框
```

- 正文写**原版 CP932 原文**（含 `%K%P`、ruby、`\n`），显示文本由外部文本替换表按位置整体替换；占位符正文会让替换表缺条目时露出占位串。
- 说话人经映射表译成 `%LC` 英文名（表由调用方注入 `ConvertOptions.speaker_map`）；**表外名字原样保留**（按 CP932 编码，日文名用 ASCII 编码会抛异常）并告警。
- `%N`/`%P` 纯翻页标记格**不发任何 `15`**（它沿用当前名字框，补设名/清框会误清名字框；CROSS†CHANNEL 原生 1,378 例零前导 `15`）。
- 原生写法是**每句成对**：`15[设名] 14 15[清框]`，逐句如此、连续同角色照样重发（CROSS†CHANNEL 原生 97,904 条 `15` 没有一条游离在 `14` 之外）。
- **id = 字符串池序号**：`14` 的 id 与选项表 `0f` 条目的 strid 属于同一个按**文件出现顺序**填充的池，选项文本也占槽位，所以 id 会跳过被选项占用的号。转换器用同一计数器发射，id 与原版 WSC 的 id 逐项相等，可直接当文本替换表的锚点。

### 2.2 背景块（WSC 0x46 / 0x48-05 → ~106B）

```
16 00 00 | 64 00 | 37 2a 00      ← 图层块 + 渐变标记 + 停全部动画
33 bg01 00 <名>.PNG 00 01 01     ← 加载图像（flags 恒 0101）
04 LAYER_ORDER 00                ← 图层槽注册表
09 00 0a..0d 00 00 80 3f ×4      ← 图层透明度 1.0
46 bg01 00 <19B 全零>            ← 无补间
65 00 00 00 <f32 渐变秒> 00000000 0200   ← 渐变（首操作数恒 0x00）
16 01 00                         ← 重开对话框层
```

渐变秒取自紧邻的 `22 <u16 ms>`（ms/1000），无则取默认 1.0；背景块之后的首个 `4a`（渐变等待）已并入 `65`，不再单独发射。`65` 的首操作数**恒为 0x00**（见 §5 陷阱 4）。

### 2.3 立绘块（WSC 0x48-立绘族 → 34 + 39 + LAYER_ORDER + 46 重置 + 46 位置）

```
34 st0n 00 <名>.PNA 00 01 01                        ← 把 PNA 绑定到句柄（槽）
39 st0n 00 02 01 04 03 00 00 00 01 00 02 00         ← 该 PNA 的哪几帧
04 LAYER_ORDER 00
46 st0n 00 06 00 f0 [f32 10, 11, 12, 13]            ← 重置（占位值，恒定）
46 st0n 00 00 00 00 [f32 x, -40, 0, 0]              ← 位置（原点=屏幕中心，单位像素）
```

- **两条 `46` 恒成对**：第一条清掉上一次的变换（CROSS†CHANNEL 原生 7,668 组恒为 `06 00 f0` + 四个占位 f32），第二条给出真实坐标；背景块不重置、只发一条 `46` 且位置恒 `[0, 0, 0, 0]`。
- **`39` 的帧号 = PNA 记录表下标**，形态只与目标 PNA 的**记录数**有关：4 条记录 → `02 01 04 [3, 0, 1, 2]`（大图 + 3 个表情补丁）；1 条记录 → `02 01 01 [0]`。照抄 4 条形态去调 1 条记录的 PNA 会**子图层越位**。
- **槽（`34` 的句柄）不决定位置**：同一槽名在原生语料里左右两侧都出现过，位置只在 `46`。原版侧的槽位判定近似：在场 1 人 → 主槽；源槽 3 且槽 4 同时在屏 → 「同框第二张」槽；**句柄选择的实质是「别撞上宿主正在用的那一个」**（同句柄 → 新图顶掉旧图）。槽名、`0x39` 帧数形态、立绘族判定都是单语料标定值，经 `ConvertOptions` 注入。
- **位置**：原版 `0x48` 的 xabspos（有符号 u16、原版屏幕 1/128 栅格）到 Steam 的离散站位 `{0, ±275, ±400}` 是**多对一**，且同一原版 x 在不同场景会落到相反侧——**不存在纯 x 的函数**（Steam 对场景重新编排）。转换只能用单调分档启发式（`steam_x()` + `(上界, 输出值)` 阶梯）保证大致的左/中/右，**不是标定结果**；不落档的逐条关系经 `ConvertOptions.position_overrides` / `scene_position_overrides` 覆盖。
- **原版 x==0 是贴屏幕左缘**（引擎 handler 无 x==0 分支，见 [../engines/willplus/wsc-opcodes.md](../engines/willplus/wsc-opcodes.md)）；把 x==0 特判成居中是已知偏差，`ConvertOptions.x_zero_left=True` 可改为照常走分档。
- 立绘目标资源不在可用集合里时**不发射**并计数（绝不产出悬空引用——`33` 硬加载缺资源会卡死引擎）。

### 2.4 音频三兄弟（语音 / SE / BGM 的 22/22/17B 定长尾段）

| WSC | WS2 | 尾段 |
|---|---|---|
| `23 ... <语音名>` | `2e 28 <通道> 00 <名>.OGG 00` + **22B** | `00×10 0a 00 00 65 00×8` |
| `00 00 00 <SE名>` | `28 se01 00 <名>.OGG 00` + **22B** | 模态形态 `00×10 0a 00 00 00 00 00 00 01 00 00 00 00` |
| `0a ff … <BGM名>` | `1e bgm01 00 <名>.OGG 00` + **17B** | `f32 vol · f32 0 · u16 0xffff · u16 0x000a · u8 1 · f32 0` |

- 三者同源（`2e 28` 前缀、`28`/`1e` 共有的 `0xffff`/`0x000a` 标记指向同一套「槽内音频」参数块），尾段必须按 **22/22/17 字节整条读**，少读的字节会被当成下一条指令。
- 语音指令紧贴其对话行之前；`0x23` 后跟非对话指令时**原位补发**，保持音频时序。
- 通道名不能套「char + 前缀」：原版语音名前缀与 Steam 通道名是两套字母序列，必须查表（`ConvertOptions.voice_channel_map`），查不到就报错而不是回退。
- **语音编号体系完全不同**：原版按「角色 + 场景块 + 变体 + 行」命名，Steam 按角色全局重编，二者无换算关系——不能引用 Steam 原生语音名，原版语音须按原名补入。
- 原版语音采样率若与 Steam 侧不一致（CROSS†CHANNEL：原版全 44100、Steam 全 48000），补入前统一重采样。

### 2.5 选项（WSC 0x02 → 0e/0f 表）

```
WSC:  02 <count> 00 { <u16 sid> <文本> 00 | 11B 选择器 } ×count
   ↓
WS2:  0e 0b 00 <count> 00 01
      0f <count>
      × count: <u16 strid> <文本 CP932> 00 00 <u16 label=0x0b+i> <跳转>
      跳转 = 06 <u32 输出文件内偏移>  |  07 <脚本名> 00
```

- **strid = 字符串池序号**（= 该处对话 id 计数器），不是 0 基表内序号；写成 0 基会让选项文本与字符串池错位。
- 分支目标解析逐选项进行：① 文件内 `06` 分发阶梯（按**位置**取选项块之后第 i 条 `06`，不按条件值排序）；② Steam 对应脚本的选项表收割；③ 不足处回退到本脚本出口并告警。**同一脚本的多张选项表逐表对应**，不能跨表复用目标。
- 阶梯中 `01 var=…` 赋值体被丢弃并计数——WS2 选项直接跳转，无处承载该状态变量（hub 型系统脚本的语义损失，需在调用链层重建）。

### 2.6 场景出口（WSC 0x07/0x09/0xff → 07 | ff a b）

```
WSC:  07/09 <目标> 00（仅当位于有效文件尾，其后仅 0a/ff）   或   ff <u32 a> <u32 b>
   ↓
WS2:  07 <目标> 00 | ff <u32 a> <u32 b>
```

出口目标**绝不猜测**：显式改写表（`exit_target_map`）> Steam 对应脚本收割 > 选项脚本原生无 `07` 出口 > 输出终止型 `ff` 并告警（等调用链整合接线）。

### 2.7 BGM 音乐鉴赏 id（0b）

`0b <u16 id> 01` 的 `id = 基数 + 曲目号`。基数是**单语料标定值**：CROSS†CHANNEL 语料实测 1049（BGM015→1064，25 曲全吻合），**跨作需重验**，经 `ConvertOptions.bgm_id_base` 注入；未注入时转换器跳过 `0b` 发射并告警。

## 3. 两代引擎的关键语义差异（7 条）

1. **对话 id 两边都是 u16**——`14 <id:u16> 00 00`，不存在「WS2 id 为 u8」的读法（id≥256 的原生文件实证）。
2. **WS2 的 `07` 无 `ff 08` 尾**——`07 <目标> 00` 与 `ff a b` 是两条独立指令，不能写成一个指令。
3. **原版 07/09 兼有调用语义**：语料实证 `07 EVRET`、`09 RestBGM`、`09 CG_WAIT` 之后仍有数十条活指令（call-and-return），而 WS2 的 `07+ff` 是终止语义、无等价调用——**只有位于有效文件尾（其后仅 0a/ff）的转移才映射为出口**，中程转移一律跳过并告警、后续内容线性保留。
4. **原版文件尾选项由引擎路由**：分支不在脚本内（见 §1）；Steam 版必须显式落成 `0e/0f` 表 + `06/07` 跳转，目标需另行求取。
5. **`ff a b` 两引擎同构**：`b=128/192` 与「含选项」强相关，原样保留；`a` 是引擎内部参数（原生取值非常分散），转换统一取一个实测可玩值即可——CROSS†CHANNEL 语料实测 `a=8` 可玩（`a=0` 会崩溃），跨作需重验。
6. **语音编号体系完全不同**：原版按「角色 + 场景块 + 变体 + 行」，Steam 按角色全局重编，无换算关系（§2.4）。
7. **第三方补丁的还原脚本不是忠实转换**：与原版逐句对齐后错位、文本可能被占位符替换——其产物只能当字节模板与命名参考，不能当信源；这也是需要逐指令忠实转换器的原因。

## 4. 切片模式（就地插入宿主脚本）

`convert_range(wsc, stem, opts, start_offset, end_offset)` 按 WSC 字节偏移区间转换（左闭右开，端点必须落在指令边界）。`opts.slice_mode=True` 表示这段产物**接在宿主脚本中间**而不是做成独立脚本，四处行为不同：

| | 独立脚本 | 切片（`slice_mode=True`） |
|---|---|---|
| 出口 `07` / `ff` | 发射出口 | **跳过**，由宿主保留的出口尾段承担 |
| 文尾 `0a`（停 BGM） | 由出口交接口音频，丢弃 | **照常发射**，否则插入段结尾漏掉停 BGM |
| 开头 `16 01 00`（开对话框） | 需要 | **抑制**，宿主此时对话框已开 |
| 字符串池序号 | 从 0 起 | 从 `opts.pool_start` 起 |

**`pool_start` 必须等于前段保留下来的对话数**：`14` 的 id 等于文件内出现序（CROSS†CHANNEL 原生 363 个脚本中 354 个满足 `id == 0..n-1`，9 个反例全是有 `0f` 选项表的脚本），插入段接续这个序号才能对上字符串池。切片后 label 仍以 WSC 绝对偏移为键，`06` 的文件内跳转只要两端都在切片内就照常解析；切片外的目标告警并指到切片末尾。立绘槽位判定需要**整脚本**上下文，切片转换经 `ConvertOptions.slot_context` 传入全量指令流（切片只决定转哪一段，不决定槽位判定）。

## 5. 实现陷阱（改代码前必读）

1. **`15` 空前缀是 `15 00 00`**（prefix NUL + 尾 00）——少一字节会把下一条 `14` 吃进 prefix。
2. **定长尾段必须按整条指令读**（`28`=22B、`1e`=17B、`2e 28`=22B，见 §2.4）：少读的字节**恰好**能解析成合法指令，覆盖率检查照过、往返比对也自洽——这类错误只能靠第二实现或全语料逐字节模态发现。
3. **`0x34` 槽名是一个完整 NUL 串**（`st01`..`st12`）：发射时直接写 `34 "st03" 00`，若再补一个 's' 前缀字节会产出非法的 `sst03`；注意 `0x34` 另有 tag=`0x40`（'@'）的 `@ANIMATION_SETKEY` 形态，检查槽名要按 tag 分流。
4. **`65` 的首操作数恒为 `0x00`**：`65 64 00 00` 属于 `66` 蒙版块**自己的**尾巴，混用会写出原生不存在、引擎侧未验证的参数。
5. **说话人前缀按 CP932 编码写入 `%LC`**：表外说话人是日文名，用 ASCII 编码会直接抛 `UnicodeEncodeError`。
6. **`15` 每句成对，不得压缩、也不得在块前补**：相邻 `15` 一律原样保留（折叠会把原生清框压掉）；背景块 / 出口 / 选项表**之前都不清框**。
7. **重排脚本字节后必须重算 `01` 的文件内绝对偏移 a/b**：`01` 指令的 `a`/`b` 是按 opcode 定义的文件内绝对字节偏移（与 mode 无关），0 表示无此目标；条件双出口、跳转表类偏移同理。
8. **解密只做一次**：ror 2 不是自逆运算，语料库里的 WSC 若已是解密形态（首字节 `8c`）不要再过 `decrypt_wsc`，只有归档直读的存储形态才需要。
9. **`0x48` 的参数域在 fields 里是 hex 字符串**：`params[:2]` 是两个字符不是两个字节，按字节取值要先 `bytes.fromhex`。
10. **立绘句柄与位置都不要从 `0x64` 取**：原版位号开关是 `0x48` 之后的 `0x49 <slot> <flag>`，位置内联在 `0x48`/由 WS2 侧 `46` 给出；`0x64` 的首操作数与位号、变体都无相关性，用它取句柄会让立绘绑到别的通道、与原生立绘重叠。
11. **选项条目的 `06` 占位 fixup 偏移必须按条目实际长度（`len(head)`）计算**，不能写常数；u32 占位（如 `@@@@`）在两遍发射的第二遍由 `apply_fixups` 统一回填为输出文件内偏移。

## 6. 转换器用法

实现：`galrev/convert/wsc2ws2.py`（`convert` 全脚本转换、`convert_range` 切片转换、`ConvertOptions` 参数、`decrypt_wsc` re-export）。**库内不内嵌任何单部游戏的标定值**——说话人映射、语音通道表、BGM id 基数、立绘族正则、站位分档、槽名、逐条位置覆盖全部经 `ConvertOptions` 由调用方注入；缺省时相应功能要么报错（该报错的：`0x48` 判族、语音通道），要么降级 + 告警（`bgm_id_base`、`position_tiers`），绝不静默写错。

```python
from galrev.convert.wsc2ws2 import convert, ConvertOptions, PORTRAIT_RE, POSITION_TIERS
from galrev.willplus.decrypt import decrypt_wsc

opts = ConvertOptions(
    speaker_map={'太一': 'Taichi'},            # 原版 0x42 说话人标记 -> %LC 英文名
    voice_channel_map={'YOU': 'charYOU'},      # 语音名前 3 字母 -> WS2 通道名
    bgm_id_base=1049,                          # CROSS†CHANNEL 语料实测，跨作需重验
    portrait_re=PORTRAIT_RE,                   # 立绘族判定（^T[CB]）
    position_tiers=POSITION_TIERS,             # 站位分档阶梯（启发式，非标定）
    portrait_slot_main='st03',                 # 主槽 / 「同框第二张」槽
    portrait_slot_second='st05',
    rename_map={'EVCC0001': 'EVCC9007'},       # 资源重命名
    exit_target_map={'CCC0005': 'CCC0006_EN'}, # 出口改写
)
ws2_bytes, report = convert(decrypt_wsc(raw_wsc), 'CCC0005', opts)
```

`report` 逐指令计数：`emitted` / `skipped` / `warnings` / `dialogues` / `voices` / `images` / `sounds` / `masks` / `choices` / `exit` / `dropped_tail` / `dialogue_wsc_ids`。转换铁律：每条原版演出指令要么映射为等价 WS2 序列，要么明确跳过并计入 report——**绝不静默丢弃、绝不添加原版没有的内容**。产物入包前必须清零资源缺口清单（`33` 硬加载缺资源会卡死引擎）。
