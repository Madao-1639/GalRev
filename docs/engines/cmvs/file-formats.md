# CMVS 文件格式

判型只看头 4 字节，不要靠扩展名：

| 头 4 字节 | 格式 | 说明 |
|---|---|---|
| `PS2A` | 脚本容器 | 剧情/界面逻辑，明文（头部+载荷经字节变换，但变换参数在头里） |
| `PB3B` | 图像容器 | 界面贴图、CG、立绘 |
| `CPZ7` / `CPZ6` | 资源封包 | 多成员打包，成员名与密钥由脚本在启动时传入 |

## 1. PS2A 脚本容器（`.ps3`）

```
+0   char[4]  "PS2A"
+4   u32[11]  头部字段
+48  载荷
```

头部 11 个 u32（小端），下标即字段序：

| # | 字段 | 含义 |
|---|---|---|
| 0 | `48` | 头部长度，恒为 48，可作为自检 |
| 1 | `version_raw` | 版本原值 |
| 2 | `key` | **字节变换的参数**（不是加密密钥，明文存储） |
| 3 | `label_count` | 标签数，载荷首段是 `label_count * 4` 字节 |
| 4 | `code_size` | 代码段字节数 |
| 5 | `unknown_size` | 未命名段字节数（名称未知，**如实记录**） |
| 6 | `text_size` | 文本段字节数，字符串池 |
| 7 | `entry_pc` | 入口偏移 |
| 8 | `compressed_size` | 非 0 → 载荷做过 LZSS |
| 9 | `decoded_size` | 解压后长度 |
| 10 | `reserved` | 保留 |

**载荷布局**：`labels(label_count*4) | code(code_size) | unknown(unknown_size) | text(text_size)`。

**字节变换**（作用于编码后的字节，逆变换即编码）：

```
shift = (key >> 20) % 5 + 1
xor   = ((key >> 3) + (key >> 24)) & 0xFF
plain = ror8(((enc - 124) & 0xFF) ^ xor, shift)
```

自检：变换后载荷长度必须等于 `label_count*4 + code_size + unknown_size + text_size`。

**LZSS**：`compressed_size != 0` 时才启用；2048 字节环形窗口，写指针从 `0x7DF` 起，
flag 字节低位先、`1`=字面、`0`=引用；引用 `offset = b1 | ((b2 & 0xE0) << 3)`、
`length = (b2 & 0x1F) + 2`。

> **`compressed_size = 0` 时引擎完全跳过 LZSS**：这是补丁脚本可以「不压缩直接写」的依据，
> 也是编码器最省事的形态。引擎不校验 checksum。

**字符串引用**：表达式形态 `[01 02 20 01][u32 offset][0f 02]`，`offset` 是 text 段内字节偏移，
NUL 结尾。读取时把 text 段按 `\0` 切开即可拿到全部条目（含空串）。

## 2. PB3B 图像容器（`.pb3`）

```
+0   char[4]  "PB3B"
+8   ..+52   44 字节，**加密后**才是真实头部
+24  u32 分块边长（常见 16）
+28  u16 codec 类型
+30  u16 宽 / +32 u16 高 / +34 u16 位深（24 或 32）
+44  u32 flags 区偏移 / +48 u32 data 区偏移
```

**头部 8..52 自加密**，且依赖**文件尾部字节**：

```
plain[8+i] = (enc[8+i] ^ raw[len-3 + (i%2)]) - raw[len-47 + i]     # i in 0..43
```

⇒ 若只改了载荷长度（例如重编码），尾部字节位置随之改变，必须用**最终**产物回填头部。
这是本格式最容易踩的坑。

**codec 类型**（`cmvs-core` 与 CMVS-Engine `Pb3Decoder` 一致）：

| type | 含义 | 本库 |
|---|---|---|
| 1 | 通道分离 + 分块标记 + LZSS 位流 | ✅ 解码 + 编码 |
| 2 / 3 | JBP1 差分编码（+ alpha 段） | 仅记录 |
| 4 | 裸数据（直接当位图） | 仅记录 |
| 5 | 预测器 + 逐像素累加 | 仅记录 |
| 6 | 外部底图引用（头里带加密的基图名） | 仅记录 |

### type 1 布局

两个独立区，各先放「每通道一个 u32 长度」表，再按 **B、G、R、(A)** 顺序连续存放：

- **flags 区**每通道块：`u32 分块标记字节数`、`u32 整块同值块数`、`u32 字面像素数`，
  随后是分块标记（高位先，`1`=整块同值）、每块一个的常量值、LZSS 位流。
- **data 区**每通道块：字面像素字节。位流 `1`=引用、`0`=字面，8 个 token 一个字节。

**字面像素是「分块优先」序**，不是整幅光栅序：

```
for y 块: for x 块: for 块内每一行: 取该块该行的 columns 个像素
```

编码器必须按同序发射，否则首个分块之后的像素整体错位。

**只解码不解压时的坑**：「整块同值」分支的常量下标与「字面」游标是**两个独立计数器**，
混用会让整块同值的块取到错位数据（症状：原生图解码出彩色噪点）。两者必须分开累加。

### 全字面编码策略

不写 LZSS 匹配器也能正确产出：**分块标记全 0 + 常量块 0 个 + 位流全 0 字节 + 全量字面**。
体积约为原图的 1.8 倍，但引擎不校验 checksum，正确性优先。

### 位深：24 与 32 并存，替换时必须与原图一致

`+34` 的位深有两种，都常见：

| 位深 | 通道 | 典型用途 |
|---|---|---|
| 32 | B,G,R,**A** | 界面贴图、需要透明叠加的图 |
| 24 | B,G,R | 背景、遮罩、特效、过场（本来就没有 alpha 语义） |

- **解码**：24 位图只有 3 个通道块，解码后需补 `alpha = 255` 才能当 RGBA 用。
- **alpha 有真实语义**：32 位的界面图里，滑条 / 输入框 / 勾选框靠 alpha 混合，
  **编码时必须原样保留**。把整图 `convert('RGB')` 再转回 RGBA 会把这些控件糊成不透明色块。
- **编码必须按原图位深输出**：把 32 位数据放到原本 24 位的位置会多写一个通道块，
  引擎按 24 位解析就通道错位（症状：偏色、竖条）。反之亦然。
- **编码器的接口约定**：输入恒为 4 字节/像素的 RGBA，输出通道数由 `bpp` 决定
  （24 时丢弃 alpha）。转换只发生在编码器内部，调用方不必关心位深差异。

> 反例：编码器写死 32 位、调用侧又额外校验「原图必须 32bpp」，会让 24 位原图对应的图
> 被整批跳过（本项目实测漏掉 5 张演出图）。筛选条件只应校验尺寸，位深由编码器按原图决定。

## 3. CPZ 资源封包（`.cpz`）

`CPZ7` / `CPZ6`。成员名与索引密钥**由脚本在启动时作为参数传入**，所以静态解析封包需要
先解析 `start.ps3` 里的挂载命令（见 [engine-mechanics.md](engine-mechanics.md) §1）。
本库未实现；参照：CMVS-Engine `CPZV6Unpacker`（仅 v6）、GARbro。

> 成员名是 ASCII/Shift-JIS 定长字段，**不要用 UTF-16LE 解**——它会把偶数长度名字静默解成乱码
> 且不抛异常。
