# CMVS 文本渲染与编码通路

CMVS 的文本渲染**没有自己的字形光栅器**，它把字节合成 16 位码位后交给 GDI。
因此换文本编码（Shift-JIS → GBK / UTF-8）只需要动三处，且**三处都必做**。

## 1. 渲染链路

```
脚本 strings  →  引擎把两个字节合成 16 位码位（大端 [lead][trail]）
              →  CreateFontA(... iCharSet, face)
              →  GetGlyphOutlineA(hdc, 码位, ...)   ← 由 LOGFONT.lfCharSet 决定怎么解释码位
              →  GDI 字形掩码
```

- 字体创建只有 `CreateFontA` 一族（`CreateFontIndirectA` 也可能出现），
  `iCharSet` 通常只有两档：`0x80`(SHIFTJIS) 或 `0x00`(ANSI)，来源是配置文件里的
  `FONT_SHIFT_JIS` 之类开关。
- exe 内通常**没有** `MultiByteToWideChar` / `AddFontResource*`，`SetWindowTextA` 等一律 ANSI。
- **转码完全由 charset 决定**：实测同一 16 位码位，charset `0x80` 与 `0x86`(GB2312)
  交给 `GetGlyphOutlineA` 得到的是不同字形，与 `GetGlyphOutlineW(对应 Unicode)` 可逐字节比对。

### 改成目标编码要做的三件事

| # | 动作 | 不做会怎样 |
|---|---|---|
| 1 | `CreateFontA` 的 charset `→ 目标值`（GBK = `0x86`，UTF-8 需要另行处理） | 字显示为豆腐块 |
| 2 | **双字节判定**放行目标编码的首字节范围（见 §2） | 字能显示，但「一个字占几格」按半角算，正文框缩窄一半 |
| 3 | **标点禁则**换到目标编码码位（见 §3） | 标点落在行首 |

> **没有任何配置项或脚本命令能改变 charset**（那个可在脚本里切换的标志是「双字节排版模式」，
> 与 charset 无关）。所以换编码**必须改代码**。

## 2. 双字节判定

引擎把「首字节是否引导双字节字符」内联了多份（跨作数量不同，实测 9 份），
两支汇编形态混排：

```asm
; 第一支
cmp X, 0x81
jb  single
cmp X, 0x9F
jbe double

; 第二支（8 位回绕技巧）
lea t, [X+0x20]
cmp t, 0x1C
jbe double
```

第二支等价于 `X ∈ 0xE0..0xFC`（因为 `(X+0x20) & 0xFF ≤ 0x1C`）。

原生 SJIS 的接受集合 = `0x81-0x9F ∪ 0xE0-0xFC`。

**GBK 的合法首字节恰好是 `0x81-0xFE`**，所以只要把第一支的立即数 `0x9F` 改成 `0xFE`，
接受集就变成 `0x81-0xFE`（第二支仍匹配 `0xE0-0xFC`，是前者的子集），**与 GBK 完全一致**。

> 另一种实现方式是把整个判定函数换成 `return X >= 0x80`（函数级替换，需要 detour）。
> 两种做法在 GBK 下**结果等价**，改立即数更小、更容易回退。
>
> 陷阱：`3C 9F` 与 `80 F? 9F` 两种编码会混排，必须按**立即数字节**定位，不能按指令地址猜。

## 3. 标点禁则（行首禁则）

引擎的换行判定里硬编码了一组「不落行首」的码位，形态如下：

```c
// 允许换行 ⇔ 当前行还有空间，且（禁则功能关闭 或 当前字符不属于禁则集合）
if (remaining >= 0 && (rule_disabled ||
     (ch != C1 && ch != C2 && ch != C3 && ch != C4)))
    advance_to_next_line();
```

**实测集合是 `、 。 」 』`**（SJIS `0x8141 0x8142 0x8176 0x8178`）。
注意 `0x8176/0x8178` 是**右引号**，不是逗号句号——按印象猜字符会写错映射表。

这个判定会在多个函数里被内联（实测 8 份，共 32 处比较），全部是等长
`mov r32, imm32`（5 字节），因此**只改立即数的低 2 字节**即可，指令长度不变。

GBK 映射（`cp932` / `gbk` 实测对照，不要凭印象写）：

| SJIS | 字符 | GBK |
|---|---|---|
| 0x8141 | `、` | 0xA1A2 |
| 0x8142 | `。` | 0xA1A3 |
| 0x8176 | `」` | 0xA1B9 |
| 0x8178 | `』` | 0xA1BB |

> 偏移陷阱：`mov r32, imm32` 的立即数**低字节在 opcode 之后**（`VA+1`），高字节在 `VA+2`。
> 把 rva 直接算成指令起始地址会让校验读到 opcode 字节而全部 MISMATCH。
>
> 台词大量用 `「」『』` 包裹时，禁则失效的观感问题非常明显（标点被推到行首）。

## 4. 排版宽度

除了「双字节判定」，部分构建另有 `CalculateLength` 一族函数计算每字符占几格。
若换编码后出现「字数对不上但字符都是对的」，检查这一族是否也需要把码位换掉
（参照实现里补的同样是 `A1A1`–`A1BB` 区间）。是否存在、有几处，**跨作需重验**。

## 5. 标题栏

窗口标题由 `SetWindowTextA` 设置，内容来自启动脚本里的一串 ASCII +
可能夹着 SJIS 全角空格 `81 40`。在 GBK 模式下 `81 40` 会被解成「号」之类的乱码字。

两种处理方式：

- **转宽字符**：先判字节是 SJIS 还是目标编码，`MultiByteToWideChar` 后调 `SetWindowTextW`。
  更通用，但改变了 API 语义。
- **等长替换**：`81 40` → GBK 全角空格 `A1 A1`（都是 2 字节），其余字节原样透传。
  更小、更容易回退，适合只想修乱码的场景。

> 启动脚本里挂载的目录（如 `data/update/`）在该脚本自己被读到**之前**还不存在，
> 所以放进那些目录的同名启动脚本**永远不会被读到**——标题串只能靠钩子改，
> 或者直接改 `data/code/start.ps3`（不是外挂形态）。

## 6. 字体

见 [engine-mechanics.md](engine-mechanics.md) §5（三条硬性要求）与 §6（改默认值）。
字体目录化注册的形态：扫描补丁目录下全部 `.ttf` / `.otf`，
用 `AddFontResourceExA(..., FR_PRIVATE, 0)` 私有注册（只对本进程可见、免安装），
玩家可自行增减。`AddFontResourceExA` 返回非 0 **不代表**字体已可用，
注册后应真实枚举一次（同 charset、`fonttype=4`）确认。
