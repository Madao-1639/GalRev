# Steam 成就机制与注入

本文档覆盖 AdvHD 引擎 Steam 版的 CG 类成就机制：脚本里成就的固有 id 对、Steam 编译器追加的成就调用、以及把成就调用注入新增内容时的工程要求。相关原语：`galrev.advhd.ws2`（`DISPLAY` 正则、`find_display_sites`、`read_id_map`）、`galrev.advhd.ws2patch`（绝对偏移重写与边界自检）。

## 固有 id 对：成就 id 永不需要自己发明

每条 `0x34` 显示 CG 的指令之后恒跟两个 `0x0b` 变量设置指令，携带该 CG 的画廊 id 与差分 id：

```
34 <槽>\0 <STEM>.PNA\0 01 01   0b <u16 画廊id> 04 01   0b <u16 差分id> 04 01
```

- 这个 id 对在 **Steam 版与原版脚本里都存在**——它是「显示一张 CG」的固有组成部分，与成就功能无关；对照同一场景的两版脚本逐字节比对可见，Steam 版只在 id 对之后**多出恰好 16 字节**：

```
...0101  0b <u16 A> 04 01  0b <u16 B> 04 01  [04 "CG_ACHIEVEMENT" 00]  39...
         |<------- 两版都有 ------->|  |<-- 仅 Steam -->|
```

- 结论：**成就 id 永不需要自己发明**——从原版脚本读 id 对（`galrev.advhd.ws2.read_id_map`，按 CG 基名索引；尺寸变体后缀 `L/S/M/W/X` 先剥掉），原版与 Steam 的 id 对一致。
- ⚠️ **id 对挂在哪种显示指令上是语料前提，换语料先核**：id 对紧随 `0x34` PNA 显示是「事件 CG 走 PNA 进 ev 槽」语料的形态；在事件 CG 以 `0x33` 压 PNG 显示的语料（如 CROSS†CHANNEL，实测 id 对紧随 `0x33` PNG 显示 640 处、`0x34` 后 0 例）上，要把同一模式对准 `0x33`。
- `0x0b` SetFlag 属**演出无关指令**：做两版差分重建时，这一整类指令（承载画廊/成就 id）取 Steam 侧。

## Steam 编译器追加的成就调用

Steam 编译器在每个 CG 显示的 id 对之后追加一条 16 字节调用：

```
04 "CG_ACHIEVEMENT" 00
```

引擎由此触发 CG 收录成就（画廊 id 与差分 id 取自紧邻其前的 id 对）。

## 注入原则

**只插调用，绝不重发 id 对**：注入 = 在每个缺调用的显示点（id 对之后、下一条指令之前）插入 16 字节 `04 "CG_ACHIEVEMENT" 00`；id 对的四个操作数字节保持原样，CG 自己的 id 原样复用，不重算。判定注入点用 `galrev.advhd.ws2.find_display_sites`（返回每个显示点 id 对结束的偏移与「是否已有调用」）。

⚠️ 不要用「找到 id 对就裸拼接」的一次性注入脚本：脚本里有条件与跳转时，任何字节增删都会使绝对偏移失效（见下）。

## 注入工程要求

凡在指令流中做字节增删（成就注入、拼接、改名），以下两步不可省略：

1. **绝对偏移重定位**：`0x01 Condition`（`a`/`b`，操作数偏移 7/11）、`0x02 Jump2`（操作数 0）、`0x06 Jump`（操作数 0）的目标是**文件内绝对偏移**，每个目标按「+16 × 该目标之前的插入点数」重写（`galrev.advhd.ws2patch.rewrite_targets`）；目标 0 是「不跳转」哨兵，跳过。
2. **四条强不变式自检**（全部通过才算注入成功，逐条计数为 0 即失败）：
   - 新脚本体能被 `galrev.advhd.ws2disasm` **全量 tile 对齐**（线性反汇编到 EOF、零 UnknownInstruction）；
   - 新旧脚本的**指令流差 = 仅成就调用**（逐指令比对 opcode+操作数，除插入的调用外不允许任何差异）;
   - **偏移变化量精确**：每条受影响指令的偏移增量等于其之前插入字节的累计值；
   - **跳转目标落指令边界**：所有 `01.a/01.b/02/06` 的目标必须落在指令首字节（`galrev.advhd.ws2patch.check_boundaries`，违规列表必须为空）。

## EVRET：任何长度改动后必须修偏移

`EVRET.ws2` 的出口结构里含一条 `0b <画廊id> 01`，且其前后字段是**绝对 u32 偏移**（指向该 `0b` 指令）：

```
<field1 u32> 01 82 6e ... <field2 u32> 07 EVRET 00 0b <gallery u16> 01 07 <next> 00
```

- `field1`/`field2` 指向 `07 EVRET` 之后的 `0b` 指令；`EVRET.ws2` 有两条出口（TITLE / 场景返回），偏移决定分支走向。
- **任何**改变脚本长度的操作（成就注入、差分重建、改名变长）之后都必须重修这些偏移字段并**全量复查**（不只是被改的那一处）。
