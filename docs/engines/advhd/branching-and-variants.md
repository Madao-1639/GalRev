# 条件分支与变体路由（选项帧 / 跨脚本变量路由）

本文是「在一份脚本语料里同时保留两套演绎，并在剧情分支点让玩家选择」的**引擎级做法**：
字节模板、绝对偏移纪律、以及最容易踩的变量存储陷阱。跨作复用时，**变量号与槽位编号必须回该作重标定**。

相关：[ws2-opcodes.md](ws2-opcodes.md)（`0x01`/`0x0f`/`0x14` 格式）、[engine-mechanics.md](engine-mechanics.md)（VM 与槽位）、[file-formats.md](file-formats.md)（rot6 与归档）。

## 1. 两种变量存储，别混用

| 指令 | 形态 | 存储 | 说明 |
|---|---|---|---|
| `0x0b` | `0b <id:u16> <val:u8>` | **布尔位图** | `val` 只有 0/1 有意义；写非 0/1 值**不报错**，但后续布尔比较会失去区分度 |
| `0x09` | `09 <mode:u8> <id:u16> <val:f32>` | **浮点数组** | `mode 0` = 赋值、`mode 1` = 累加；与布尔位图**是两套空间**，同 id 互不影响 |
| `0x01` | `01 <mode:u8> <id:u16> <val:f32> <a:u32> <b:u32>` | 读 | `mode & 0x80`（bit7）决定读**浮点数组**（置位）还是**布尔位图**（清零） |

`mode & 0x3F` = 比较运算符（`0 >=`、`1 <=`、`2 ==`、`3 !=`、`4 >`、`5 <`）；`mode & 0x40`（bit6）= 右操作数也是变量。
`a`/`b` 都是**文件内绝对字节偏移**，`0` = 无此目标，`a != 0` 时优先；**条件成立 ⇒ 顺序执行，不成立 ⇒ 跳到 `a`/`b`**。

### 陷阱（实测，代价极高）：布尔存储不能用来区分 1 与 2

把「原版 / 替换版」编码成 `0b var 1` / `0b var 2`，再用 `01 mode=3 (≠) var != 2` 判分支，**两个选项会走同一支**：
布尔比较把两侧都折成真值，写 2 与写 1 等价 ⇒ `var != 2` 恒假 ⇒ 永远跳向 `b` 那一侧。
症状是「选项能点、分支不生效、两段剧情一样」，且**字节形状检查全部通过**（形状合法、语义错）。

**规范**：布尔旗标只用 **0 / 1**；条件写成 **`01 mode=2 (==) var == 0 → 替换体`**
（成立 ⇒ 顺序执行 = 原版体；`var = 1` ⇒ 跳替换体）。这样还有个附带好处：**未写入也等于 0 ⇒ 缺省走原版**，
从回想/半途入口进入的脚本不会莫名变成替换版。

需要三态以上时不要硬塞布尔：改用 `09`（浮点）+ `01` 的 bit7 浮点比较。注意该路径**在本引擎语料里几乎没有先例**（某作全库 `01` 无一条 bit7 置位、`09` 仅 9 个 id），
启用前必须实机 A/B 验证。

## 2. 机制一：单文件内分歧（选项帧 + 跳转）

适合「分支两侧都在同一脚本里」的场景。原生形态（与游戏自带选项完全同构）：

```
[前奏]   15 00 00                      ; 清名字框（可有可无）
         14 <id:u32> char\0 <提示句>%K\0 00   ; 提示句：尾部 %K 留框
[选项头] 0e <0b 00> <count:u16> 00 01    ; 选项头：与 0f 的 count 必须一致
[选项表] 0f <count:u8>
           count × ( <strid:u16> <text:cp932>\0 <80 01 00> <06> <target:u32> )
[分支A]  <target> = 0b var 0 / 14 "%P"   ; 分支前奏：写旗标 + 纯标记行
         …分支 A 体…
         06 <汇合点>                     ; 非末支以跳转收尾
[分支B]  0b var 1 / 14 "%P"
         …分支 B 体…                    ; 末支顺流落到汇合点
[汇合点] 14 …                            ; 必须是台词行，前一条也必须是 14
```

纪律：
- 条目 `<text>` **不带尾部控制符**（对话格才带 `%K/%P`），提示句**必须带** `%K`；
- 每张 `0f` 前必须紧邻 `0e <count>` 头，两处 count 相等；
- 条目 `<target>` 与 `06` 汇合点都是**绝对偏移**，插删字节后要重算，且必须落在**指令起点**；
- 选项帧内不得有 `0x16`（某些作里它会关闭输入门，选项能画但点不动）与 `0x28`（语音）、不得有非空 `0x15`；
- 分支体若来自另一份语料，需要**逐指令等值**回验（`0x14` 只比正文，字符串池 id 会重排）。

## 3. 机制二：跨脚本变量路由（在目标脚本首条判旗标）

适合「一组后续脚本整体切换版本」（同一夜/同一条线的连续多场景）。做法：

```
<目标脚本> =  [01 mode=2 var == 0 → <替换体起点>] [原版体（原字节）] [替换体（原字节，整体平移）] [出口/尾表]
```

- 条件成立的路径**顺序执行** = 原版体；否则跳到追加的替换体；
- 替换体是**原字节搬运**：只把其中的绝对偏移（`01.a/b`、`02`、`06`、`0f` 条目 `06`）按整段 delta 平移；
- 两段各自以 `07 NextFile` 收束（或各自落到同一汇合点）；
- 前一个脚本用**机制一**写下旗标（例如 `0b var 0` = 原版 / `0b var 1` = 替换版），后续脚本只**读**，不再给玩家选项。

**一线一变量**：同一条角色线沿途的多个脚本共用一个变量，避免「这一场选原版、下一场选替换版」造成前后文互指矛盾（例如后一场台词回指「初夜」，而前一场走的是替换版）。

## 4. 绝对偏移与分段重定基

插入式修改后，所有绝对偏移都要重算。工程上按**分区线性映射**处理，比逐条累加可靠：

```
map(t) = t + Σ{此前各插入区的净增量}      # t 落在哪个源区间，就加该区间左侧的累计增量
```

要点：
- 汇合点/条目落点等**新造的目标**用"新流坐标"直接算，不要对旧值做 remap；
- 追加体内部的偏移整体加"追加体起点 − 源起点"这一个 delta；
- `0f` 条目的跳转字段也带绝对偏移，且**条目解析出的偏移是块内绝对量**——对单条指令做重定基时不要再叠加 `off+1`（常见 off-by-one 事故）；
- 切片/追加后必须重算**尾表**（有的作把「消息数/选项数」明文写在文件末尾 8 字节，引擎按它分配已读位图；写错会概率性崩溃）。

## 5. 自检清单（字节面能验的部分）

1. 每张 `0f` 前紧邻 `0e`，count 相等；条目落在指令起点且正对分支前奏（`0b` + `14 "%P"`）；
2. 提示句 `%K` 收尾、文本与语料一致；帧内无 `0x16`/`0x28`/非空 `0x15`；
3. 汇合点是指令起点，其前一条是 `0x14`（分支体以台词收尾）；
4. 追加体与源语料**逐指令等值**（含 `0f` 条目计数与跳转平移）；
5. 旗标写入值 ∈ {0,1}，条件为 `== 0`（或 `== 1`）；
6. 文本池等式：`lng 条数 == 0x14 条数 + Σ(0f count)`（每条选项也占一个文本槽）；
7. 尾表/出口指令按新条数重算。

## 6. 实机验证纪律（形状检查不覆盖的部分）

上面 7 条全过，也**不能**证明「两个选项真的通向不同内容」——布尔折叠那类错误在字节面完全合法。最小验收：

- 在分支点**各点一次**，比对两侧的**一句标志性台词 + 一张标志性图（或语音）**，两者必须不同；
- 若两侧相同：优先怀疑旗标写入值的区分度（见 §1 陷阱），其次才是条件极性；
- 分支体里若引用了「只在某一侧存在的素材」，确认它在该侧确实存在（资源缺失时 `0x33` 硬载入会直接卡死）。
