# WS2 指令集

本文档覆盖 AdvHD WS2 脚本的类型码、opcode 格式表、函数名对照与关键指令语义。rot6 混淆与容器格式见 [file-formats.md](file-formats.md)，VM 的引擎侧结构见 [engine-mechanics.md](engine-mechanics.md)。

**方法论红线**：同引擎样本只用于提出假设，本作自身样本才用于定案。跨作同编号的 opcode 已证实逐字节同构（见下「opcode ↔ 引擎函数名对照」），但**每部游戏实际出现的形态集合与取值域不同**——某部语料的统计（如「某字段只出现过 A/B 两种取值」）不能当成引擎定律，操作数格式与分支极性的定案必须回该作自身 exe 的格式表与 handler。

## 类型码 → 字节数

引擎的操作数解析器按 opcode 从格式表取出一个**类型码串**，逐码读取操作数：

| 码 | 含义 | 字节 |
|---|---|---|
| `0` | u8 | 1 |
| `1` / `2` | i16 / u16 | 2 |
| `3` / `4` | i32 / u32 | 4 |
| `5` | **f32** | 4 |
| `6` / `9` / `0a` | NUL 终止串（`0a` 读出后大写化） | 变长 |
| `8` | 串的 NUL 终止字节 | 1 |
| `7` | **计数标记**：其后类型重复 count 次（如 `07 01` = count × i16） | 变长 |

## 全部 opcode 的操作数格式表

164 个已实现 opcode 的格式串、操作数分解、`tail_bytes`（定长尾段 = 非串字段字节数，已扣除串终止符）见仓库级数据表 [`data/ws2_operand_formats.json`](../../../data/ws2_operand_formats.json)，本篇不再重复。该表由引擎格式表导出（来源 exe 见 [engine-mechanics.md](engine-mechanics.md)「WS2 脚本 VM」）。

## opcode ↔ 引擎函数名对照

同一函数名在不同游戏里**编号一致**：`01`/`04`/`05`/`07`/`09`/`0b`/`0f`/`14`/`15`/`16`/`1e`/`28`/`2e`/`33`/`34`/`37`/`39`/`3f`/`45`/`46`/`48`/`58`/`65`/`66`/`ff` 等已由两部观测作品的 exe handler 表逐项核对，零偏差，这张表可跨游戏使用；但具体游戏的脚本只用其中一部分。

常用项（完整表见 `galrev/advhd/ws2disasm.py` 的 `OPCODE_NAMES`）：`01` Condition、`02` Jump2、`04` RunFile、`06` Jump、`07` NextFile、`09` LayerConfig、`0b` SetFlag、`0e` Unk0E、`0f` ShowChoice、`11` SetTimer、`12` StartTimer、`14` DisplayMessage、`15` SetDisplayName、`16` Unk16（图层命令块）、`1a` OpenTitle、`1c` ExecuteFunction、`1e` PlayMusic、`1f` StopMusic、`20` MusicUnk1、`28` SoundEffect、`29`/`2a` SoundUnk1/2、`2e` CharMessageStart、`33` SetBackground、`34` UsePnaPackage、`35` PlayMovie、`37` ClearLayer、`39` DisplayCharacterImage、`3f` LayersList、`40` SetMask、`44` Effect44、`45` DragBackground、`46` MoveBackground、`47` Effect1、`48` Effect2、`51`/`52`/`53` 变量组、`56` RainStart、`57` UnkBackground1、`58` Effect3、`5c` RainEnd、`64` Unk64、`65` C65（渐变，未定名）、`66` ShowGraphic、`6e` SetVariable、`74`（未命名）、`8f`（语音+字幕）、`c9`（语音/层映射）、`e6` ConditionalJump、`ff` FileEnd。

注意两点：

- 这套函数名是**标签，不是引擎符号**：实测在观测作品的 `AdvHD.exe` 里 `DisplayCharacterImage`/`UsePnaPackage`/`SetBackground`/`LayersList` 等名字一个字符串都没有，编号与布局的正确性依据是 handler 表，不是符号名。
- **`48` 在两套引擎里是两条完全不同的指令**：WS2/AdvHD 的 `48 = Effect2`（两条 NUL 串 + 参数块，格式串实证为 `str, str, i16, u8, u8, str`）；WillPlus 旧引擎（WSC）的 `48` 是立绘显示。读原版脚本时不要混用。

## 关键指令语义

以下形态按引擎格式表与 handler 反编译确证；字节级细节以 [`data/ws2_operand_formats.json`](../../../data/ws2_operand_formats.json) 为准。

### `0x01` Condition（条件，16 字节，双出口）

```
01 <mode:u8> <id:i16> <value:f32> <a:u32> <b:u32>    # mode == 0 时只有 5 字节
```

- 操作数布局由引擎格式表**按 opcode** 决定（格式串 `00 01 05 04 04 ff` = `u8, i16, f32, u32, u32`），**与 `mode` 无关、没有 mode 门控**；同引擎参考工具按 `mode` 值门控读法，那是该作的枚举，直接照搬会读错字节数。
- `<mode>` 是位域：`mode & 0x3F` = 比较运算符（`0` `>=` · `1` `<=` · `2` `==` · `3` `!=` · `4` `>` · `5` `<`）；bit6 `0x40` = 右操作数也是变量；bit7 `0x80` = 走浮点变量数组，否则走布尔变量位图。
- `<a>` 与 `<b>` 都是**文件内绝对字节偏移**，`0` = 无此目标；`a != 0` 时优先。分支极性：**条件不成立 ⇒ 跳到 `a`/`b`；成立 ⇒ 顺序执行**（handler 把操作数直写脚本 PC）。
- `<a>`/`<b>` 常与两条 `07` 连用，形成「同一文件的两个出口」（分支转移 vs 跳过转移留在本文件）。
- ⚠️ 凡重排/插删脚本字节，**`a`（非 0 时）与 `b` 都必须重算**（按 opcode 的规则，不限 mode），否则跳到指令中间，实机症状是脚本末句之后卡死或点击无反应。重写原语见 `galrev.advhd.ws2patch.rewrite_targets`。

### `0x04` RunFile（引擎子调用）

`\x04 <name>\x00`，引擎子程序调用；绝大多数是 `LAYER_ORDER`（刷新图层登记表），**不是**场景切换指令。

### `0x07` NextFile（场景转移）与 `0xff` FileEnd（出口）

`0x07 <脚本名>\x00` 是终止型场景转移（无调用/返回概念），本身没有参数尾；其后跟**独立的** `0xff <u32 a> <u32 b>` 出口指令。观测：`ff.a` 取 `8` 可玩（某作实测，`0` 会崩溃）；`ff.b` 与「脚本含选项」强相关（128/192），其余为 0。出口前不必清框（原生出口绝大多数前面是演出块而非 `15` 清框），且出口前不能是 `\x16\x00\x00`（会被引擎当作图层命令块的参数读入，脚本随即解析失败）。

### `0x14` DisplayMessage 与 `0x15` SetDisplayName（对话与名字框）

```
14 <id:u16> 00 00 <char>\x00 <text>\x00 00
15 <prefix>\x00 00
```

- `<id>` 是**字符串池序号**：与选项表 `0f` 的 strid 同池，按文件出现顺序填充，选项文本也占槽位，所以 id 会跳过选项占用的号。
- `<char>` 原生固定为 `char`；正文是 CP932 窄字节，`%K`（等待点击）/`%P`（清框）/`%N`（空白占位）/`\d..\d`（延迟显示）为内联标记。
- **成对规则**：`15` 只对它后面第一条 `14` 生效，原生每句成对——`14` 前一条设名（空前缀 = 旁白、`%LC<英文名>` = 设名），`14` 后一条空前缀清框；没有一条 `15` 游离在 `14` 之外，`%N`/`%P` 纯标记格不带任何 `15`（沿用当前名字框）。名字框是「继承」语义：插入段落发完必须恢复现场。
- 对话格（`0x14`）正文必带尾部控制符、选项条目正文必不带——两套语料零例外，是「文本丢失」类错误的自足判据。

### `0x0f` ShowChoice（选项表）

```
0f <count:u8>  count × ( <strid:u16> <text>\x00 00 <u16 标签> <jump> )
```

每条选项的 `<jump>` 有两种形态：`07 <脚本名>`（转到分支脚本）与 `06 <u32 偏移>`（文件内跳转）——引擎允许在同一文件内做选项分歧，不必然新增脚本。`06` 的目标与 `01` 的 `a`/`b` 一样是文件内绝对偏移，重排脚本必须重算。每个选项条目各占一个 lng 槽位（见 [localization.md](localization.md)「位置对应」）。

### `0x33` SetBackground 与 `0x66` ShowGraphic（缺失容忍度对照）

- `33 <槽>\0 <FILE.PNG>\0 01 01`：**硬载入**，资源缺失时游戏**卡死（无响应）**，不弹错误码。
- `66 <蒙版名>\0 65 64 00 00 <f32> 00000000 [02 00]`：特效遮罩，缺失时引擎**容忍（静默跳过）**，仅画面瑕疵。注意蒙版尾巴里的 `65 64 00 00` 是蒙版自己的参数；引擎视角 `66` 只有一条串，其后是**独立的 `0x65`** 指令。

### `0x34` / `0x39` / `0x46`（PNA 显示三件套）

- `34 <槽>\0 <FILE.PNA>\0 01 01`：把 PNA **绑定**到具名句柄（`0x34` 把资源注册为子图层）。槽名是一个完整 NUL 串（如 `st03`），首字节就是串的一部分，不是独立 tag。它回答「哪一层」，不回答「画在哪」。
- `39 <槽>\0 02 01 <c> <c × u16 帧号>`：选显示哪几帧。**帧号 = PNA 记录表下标（0 基）**，不是 layer_id、不是坐标；长度 `≡ 3 + 2c`（见下「模态结论」）。立绘语料的典型形态：4 记录 PNA 用 `c=4 [3,0,1,2]`（大图 + 3 个面部补丁）或 `c=1 [3]`（只用大图）。
- `46 <槽>\0 <i16 mode> <u8 mask> <f32 x> <f32 y> <f32 u> <f32 v>`：**图层位置在这里**。原点在屏幕中心、单位像素；立绘 `y` 恒 -40（某作观测）。`mask` 逐位对应 4 个 f32：置位 → 该值是预设表下标，清零 → 字面值；语料只有 `(mode 0, mask 0)` = 字面坐标与 `(mode 6, mask 0xF0)` = 重置（预设索引 10,11,12,13）两种组合。立绘块恒跟两条 `46`（先重置、后定位），背景块只发一条（位置恒 `[0,0,0,0]`）。
- 槽位机制与命名限制见 [engine-mechanics.md](engine-mechanics.md)；参数细节与图层 id 规则见 [pna.md](pna.md)。

### 音频三兄弟（定长尾段）

- `1e <槽>\0 <file>\0` + **17 字节**定长尾（BGM 播放；`@10` 的 `0x0a` 是参数不是新指令，按 10 字节读会整体错位）。
- `28 <槽>\0 <file>\0` + **22 字节**定长尾（SE；槽名为 `char*` 时即语音的另一种写法）。
- `2e 28 <通道>\0 <file>\0` + **22 字节**定长尾（语音播放；`2e` 是前缀字节、0 操作数，22B 归其后紧跟的 `28`）。
- 定长尾段必须**按整条指令读**：少读的字节会被当成下一条指令，而尾段余下的字节恰好常能解析成合法指令，覆盖率检查照样通过——这类错误只能靠第二实现或全语料逐字节模态发现（见 [engine-mechanics.md](engine-mechanics.md) 的反汇编器交叉验证一节）。

### `0x65`（渐变）

`65 <u8 a> <u8 0> <u8> <f32 秒> <u32 0> <u16 mode>`，定长 12B + 1B 空串；**首操作数恒 `0x00`**（非 0 取值也存在但极少），尾 4 字节恒 0。背景切换块、遮罩块都以它收尾。

### 其他

- `09 <mode> <id:u16> <f32>`：图层权重/浮点变量设置。
- `0b <u16 id> <u8 1>`：SetFlag，短变量设置；承载画廊/成就 id（见 [steam-achievements.md](steam-achievements.md)），属演出无关指令。
- `02 <u32>`（Jump2）与 `06 <u32>`（Jump）：目标均为**文件内绝对偏移**，跳转边界自检与重写见 `galrev.advhd.ws2patch`。
- `11 <name>\0 [00] <f32>` / `12 <name>\0 <u16>`：启动/等待计时器；`11` 的分隔字节与编译版本相关（见下「模态结论」）。
- `16 <u8 a> <u8 b>`（实测 `16 00 00` / `16 01 00`）：图层命令块起始/关闭（关对话框层、重开）。
- `3f <count> count × <名>\0`：LayersList，`LAYER_ORDER.ws2` 的全部内容（见 [engine-mechanics.md](engine-mechanics.md)「LAYER_ORDER」）。

## 字节模态结论（跨作语料）

以下结论来自对两部作品共 2000+ 个 `.ws2`、约 250 万条指令的全语料逐字节模态分析（长度分布单点 + 恒定位 + 独立锚点交叉校验 + 双实现边界比对）：

- **`39` 长度 = `3 + 2c`**：`39 <槽>\0 02 01 <c:u8> <c × u16 帧号>`。长度分布 `{5,7,9,11,13}` 与 `c = 1..5` 严格一一对应，是「长度由 c 决定」的直接证据。把 c 的取值硬编码（如只认 1/4 两种）在帧数更多的语料上会每条少读 `2(c-2)` 字节，且余下字节恰好还能解析——覆盖率照过但边界已漂移。
- **`11` 双编码并存**：`<name>\0 00 <f32>`（5B 形态）与 `<name>\0 <f32>`（4B 形态）在同一文件内并存，无法用语料级开关判定；判定规则是逐条算两种读法的 f32、取「像定时器时长」的那个（判据 `v == 0.0 或 v >= 0.01`）。⚠️ 合法性判据必须从语料模态里量出来——用「0 ≤ v ≤ 600」这类拍脑袋区间会把错位读法的非规格化小数也放行，导致整体错位 1 字节而文件照样 100% tile。
- **`40` 双形态判据**：`<槽>\0 <file>\0`（第二个 name 是掩码资源文件名）与 `<键>\0`（动画擦除脚本里的单 name 形态，其后紧跟下一条指令）；判据取「第二个 name 必须是资源文件名（含 `.` 的文件名字符集）」，否则会把下一条指令吞掉。
- **`0x56` RainStart**：边界已定、语义未定的典型——效果名之后是 `u8 a`、`u16 n`、`u32 0`、10 × f32、若干标志位与 f32 块，尾部是**可变数量的 name**（实测 2 或 3 个）加收尾 4~5 字节，`size` 分布 `{102, 114}` 与两种形态一一对应；`a`/`n` 的语义、重复 name 的原因均无独立证据，不猜。

「边界已定、语义未定」的指令（如 `19` 1 字节无操作数、`42`/`74` 的 `<name>\0 <u16>`、`4a` 双串、`35` 中间字节、`52` 的末字节）全部有全语料模态 + 后继指令对齐支撑，可安全跳过；语义在拿到新证据前**不猜**。
