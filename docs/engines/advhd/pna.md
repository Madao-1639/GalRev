# PNA 分层图像

PNA（PNAP 容器）是 AdvHD 引擎的分层图像格式，承载立绘、事件 CG 与系统界面图层。布局已由两部作品语料 550+ 文件、3962 条记录全量验证（字段间不变量逐条成立、数据区恰好覆盖到文件尾）。工具：`galrev.advhd.pna`。

## 二进制布局

全部小端序：

```
+0x00  char[4]  "PNAP"
+0x04  i32      表大小字段 = 44 * layer_count + 12（仅校验用，不是文件偏移）
+0x08  i32      画布宽
+0x0c  i32      画布高
+0x10  i32      记录条数 layer_count
+0x14  记录区   layer_count × 40 字节（记录区起点是 0x14，不是 0x24）
之后    数据区   起点 = 0x14 + 40 * layer_count，按记录顺序紧邻排列
```

每条记录 10 × i32：

| 偏移 | 类型 | 含义 |
|---|---|---|
| +0x00 | i32 | `u0`：0 = 真实图层；1/2 = 动画帧组边界哨兵（无数据块，`layer_id` 存 -1） |
| +0x04 | i32 | 存储 `layer_id`：真实图层恒等于 `layer_count-1-index` |
| +0x08 | i32 | `box_x`（图层左上角，画布坐标） |
| +0x0c | i32 | `box_y` |
| +0x10 | i32 | `box_w`（== 内嵌 PNG 的宽） |
| +0x14 | i32 | `box_h`（== 内嵌 PNG 的高） |
| +0x18 | i32 | reserved（观测样本恒 0） |
| +0x1c | i32 | `double 1.0` 标记低 32 位（真实图层恒 0） |
| +0x20 | i32 | `double 1.0` 标记高 32 位（`0x3FF00000`）；哨兵两条全 0 |
| +0x24 | i32 | 数据块字节数（0 = 该图层无数据） |

- 每个非空数据块本身就是一张**完整的 PNG**（含签名与 IEND），所以「PNA → PNG」是切片而非重绘，可逐字节保真。
- `box_w/box_h` 恒等于内嵌 PNG 自身的宽高（全量验证 0 处不匹配），是「该图层的贴图矩形」，与画布尺寸无关；单图层 PNA 的贴图位置（`box_x/box_y`）同样有效。
- **记录数 ≠ 图片数**：`layer_count` 是记录条数，哨兵与空图层（size == 0）不占数据区。
- **签名扫描例外**：少数 PNA（如系统界面的 `SYS_GalleryBrowser.pna`、`Sys_Msw.pna`）在记录表描述的最后一个数据块之后还有一段既非 PNG 也无表结构的字节，随后才是若干张 PNG（数量比记录表多）。这段字节的来源机制未查明（已排除 zlib/deflate、也确认不是第二张表）。工具对这类文件回退为 PNG 签名扫描（`png_spans`），额外图层按出现顺序全部取出，跳过的字节区间记在 `Pna.holes` 里，不静默丢弃。

## layer_id 是纯位置量

- **`layer_id = layer_count - 1 - index`**：引擎从文件按顺序读图层、倒序编号——第 0 条记录 id 最大，最后一条记录 id = 0。
- 引擎显示 PNA 时引用的 layer_id 是 u16 位置量，取值必须落在 `[0, layer_count)`；越界会崩溃（错误码 0x00000039）。
- ⚠️ 合法性判断按**位置区间**，不要按记录里存储的 layer_id 字段集合去查——个别文件的存储值与位置规则不符（这也是位置量规则的实证来源）。
- **`0x39` 的帧号 = 图层表下标（0 基）**，不是 layer_id：按「下标」解释 100% 落在真实图层上，按 layer_id 解释会有约 20% 落到哨兵（-1）。判断「某差异层会不会被 `0x39` 选中」必须按下标取图层。

## u0：动画相位分组

- PNA 的图层按**动画相位分组**：`u0 = 0` 是基础帧，`u0 = 1/2` 是子图层组边界哨兵；一组通常是「若干个全画布主图」+「若干组共享同一裁切框的局部动画帧（每组对应一个差分，如眼/嘴）」。
- `Sys_ClickWait`（30 帧光标）、`Sys_Arrow`（29 帧箭头）这类 PNA 的图层是同一位置的动画帧，不是叠加层——**不要把所有图层叠成一张图看**，那对动画类 PNA 无意义。
- ⚠️ u0/哨兵不记录「哪组局部帧对应哪个全画布状态」——这个配对关系格式里没有字段可查，只能靠实机测试确认。

## 写回（重序列化）硬不变量

工具支持重序列化（`parse` → 改 Layer → `serialize`），换图层 = 换数据块 + 同步记录表，对未替换部分逐字节保真。硬不变量：

| 项 | 规则 |
|---|---|
| 记录表 box_w/box_h | **必须与该图层 data 内嵌 PNG 的 IHDR 一致**（原档即如此，换图后必须维持） |
| 记录条数 | 不变（不新增/删除图层） |
| 数据块 | 替换图必须是一张**完整 PNG**（签名 + chunk 链到 IEND、无尾随字节，`png_dimensions` 校验）；数据区按记录顺序紧邻重排 |
| 其余字段 | `u0`/`layer_id`/`reserved`/`double 1.0` 标记/画布尺寸逐字段原样保留（serialize 逐字段重建，未改图层逐字节保真） |
| **第一道闸** | `serialize(parse(blob)) == blob` **逐字节往返回归是第一道闸，不是可选项**——「只读不出错」不证明解析正确，错误假设可以藏在没人消费的字段里，第一次写回才暴露 |
| 签名扫描件 | `Pna.scanned=True`（记录表未覆盖全文件）**不支持写回**：数据区尾部未解释字节机制未查明，重排数据区可能破坏它，`serialize` 对其报 `PnaError` |

图层操作 API：`find_by_layer_id`（按位置规则定位且有数据的图层）、`get_box`、`replace_layer`（换图时自动以新 PNG 的 IHDR 更新 box_w/box_h）。

## 图片比对：只有帧池口径可用

Steam 侧除了整份替换 PNA，还会改绘留下的画面（同名、能正常加载、只有像素不同），识别只能靠比图。三种口径里**只有「图层帧池」可用**：

| 口径 | 是否可用 | 原因 |
|---|---|---|
| 合成整张画布再比 | 否 | 动画帧各占一个整幅不透明图层，展平后只剩图层表最后一帧，前面几帧被改成什么样都看不见 |
| 逐层按 layer_id 配对 | 否 | 重打包会重排图层表、把少数大层重切成许多小层，位置量对不上号 |
| **图层帧池** | 是 | 把两侧图层当成互不相关的帧集合，按解码后 RGBA 的整层哈希配对；配不上号的帧才是被改绘的内容 |

先解码再比是必须的：重编码会让按字节哈希几乎处处「有差异」。数值判读：定点擦除的差异外接框只占画面一小块、框内峰值高；重编码/整体调色的差异铺满整层、幅度低。浅色差异（峰值 < 40、占比千分之一以下）在缩略图上不可见，必须裁出差区放大目视，且「占比低 + 峰值低」不能直接当噪声——差异外接框极小时降级为待定，交人工核。
