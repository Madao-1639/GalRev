# Willplus 文件格式：老式归档与 WSC

## 老式归档（类型表 + 定长条目）

WillPlus 旧引擎的 Arc 与 AdvHD 系的 Arc 是**两种不可互读的格式**：

| | Willplus 老式 Arc | AdvHD（Steam 系）Arc |
|---|---|---|
| 成员组织 | 类型表分组，每组内 21 字节定长条目 | 单一成员表 |
| 条目 | 13 字节文件名 + u32 大小 + u32 绝对偏移 | u32 大小 + u32 相对偏移（相对 8 + 表长）+ UTF-16LE 名字 + NUL 结尾 |
| 名字 | ASCII/Shift-JIS，**不含扩展名**（扩展名即类型名） | UTF-16LE，含扩展名 |
| 偏移语义 | 绝对偏移（直接指向文件内数据） | 相对偏移（数据区起点 = 8 + 表长） |

### 结构

```
[u32 类型数]
n × [4B 类型名][u32 该类文件数][u32 条目区起始偏移]
条目区（每类一段）: 21 字节/条 = 13B 文件名（NUL 结尾填充） + u32 大小 + u32 绝对偏移
```

读取实现见 `galrev/willplus/arc.py` 的 `read_old_arc`，返回 `[(name_bytes, data)]`，名字为「原名 + '.' + 类型名」。

### ⚠️ 名字编码

名字是 **ASCII**（部分作品允许 Shift-JIS 字符），要用 `ascii` 或 `shift_jis` 解码。**不要用 `utf-16-le`**——它会把偶数长度的名字**静默**解成成对汉字乱码，不抛任何异常；实测 CROSS†CHANNEL 语料的上万条目中有上千条会因此「看不见」，且名字越长越难被人工抽查发现。这条教训适用于所有「定长名字 + 未知编码」的归档：先看字节范围再选解码器。

## WSC 脚本文件

### 混淆

存储形态是**每字节循环右移 2 位（ror 2）**，与 AdvHD WS2 的 rot6 混淆不同族：

| | WSC（Willplus） | WS2（AdvHD） |
|---|---|---|
| 解码 | 每字节 ror 2（`galrev.willplus.decrypt.decrypt_wsc`） | 每字节 rot6（`galrev.advhd.ws2`） |
| 自逆性 | 不是自逆——对已解密数据再解一次会解坏 | 同左 |

判断是否已解密可看首字节：明文剧情脚本以指令头 `8c` 开头。

### 文件头

- 头指令：`8c <u16 全局脚本号> 00`，其后可选一条 `e0 <章节标题 CP932> NUL`。
- CROSS†CHANNEL 语料中 301 个剧情脚本带头、23 个系统脚本（`BGM_*`、`MAINMENU` 等）无头——单语料统计，跨作需重验。
- 全局脚本号是**引擎路由的键**（见下文「脚本路由」），不是文件内序号。

### 文件尾

CROSS†CHANNEL 语料 324/324 个文件恒定为：`0a 00`（停 BGM）+ `ff <u32 a> <u32 b>`（脚本结束）；`b` 取 128/192 与「含选项」强相关。单语料统计，跨作需重验。

### 脚本路由：与 Steam 版的根本差异

- **原版按全局脚本号路由**：剧情脚本的「下一幕」**不写在 WSC 里**。实测 CROSS†CHANNEL 语料中，一个脚本的选项块之后直接 `0a ff` 结束，分支由引擎按脚本号 + 选择结果分发；56 个选项块中 42 个属于这种「文件尾选项」。单语料统计，跨作需重验。
- **Steam 版（AdvHD）要求显式出口**：每个 `.ws2` 以 `07 <目标脚本> 00 | ff <u32 a> <u32 b>` 收尾。
- 由此，把 WSC 内容搬进 WS2 时**必须补出口**，且文件尾选项的分支目标必须另行求取（Steam 语料、调用链重排等途径）；转换器**绝不猜测**出口目标，处理方式见 [../../cross-engine/wsc-to-ws2.md](../../cross-engine/wsc-to-ws2.md)。
